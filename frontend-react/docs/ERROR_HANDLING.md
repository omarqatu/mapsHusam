# معالجة الأخطاء

## في الواجهة

كل طلب API يجب أن يفحص:

1. نجاح الاتصال `response.ok`.
2. نجاح العملية داخل JSON مثل `data.success`.
3. وجود البيانات المطلوبة قبل تحديث الواجهة.

صفحات `public` تستخدم رسائل للمستخدم و`console.error` للتشخيص. لا تترك زرًا في حالة تحميل أو تعطيل دائم بعد فشل الطلب.

## في لوحة مزود الخدمة

فشل تحديث الحالة يعيد الواجهة إلى الحالة السابقة ويعرض سبب الخطأ. لا تعتبر العملية ناجحة إلا بعد تأكيد الخادم.

## في الخريطة والبحث

إذا فشل GeoServer أو API، يجب إبقاء الصفحة قابلة للاستخدام، مع رسالة واضحة وعدم مسح كل النتائج بلا سبب.

## في الخادم

`server.js` يجب أن يعيد JSON متناسقًا للحالات 4xx و5xx، ويسجل التفاصيل داخليًا دون كشف أسرار قاعدة البيانات للعميل.
