# دليل التشغيل والاختبار — منصة «دليلك وين»

> **دليلك وين — دليلك الأمين لكل خدمة وعقار**
> يشرح هذا الدليل التعديلات الجديدة، طريقة تشغيلها وضبطها، صلاحيات كل دور، وسيناريوهات الاختبار التي نُفّذت ونتائجها.

## 1. ملخص التعديلات

| # | المطلب | ما تم تنفيذه |
|---|--------|--------------|
| 1 | المزود يضيف أكثر من خدمة ويعدّلها ويرفع صوراً | صفحة **«خدماتي»** `/my-services.html` + جدول ملكية متعددة `provider_listings` + رفع حتى 8 صور لكل إعلان (تُضغط تلقائياً بالمتصفح وتُخزَّن داخل قاعدة البيانات `listing_images`) |
| 2 | شاشة مخصصة للعقارات والتعديل عليها | صفحة **«عقاراتي»** `/my-properties.html` (شقق إيجار / شقق بيع / أراضٍ): السعر والعملة والمساحة والحالة والموقع والوصف والصور |

| 5 | اسم مناسب للمنصة | **«دليلك وين»** مع الشعار «دليلك الأمين لكل خدمة وعقار» (قابل للتغيير من لوحة الإدارة دون تعديل الكود) |
| 6 | واتساب المنصة + رقم الهاتف | زر تواصل عائم بكل الصفحات + روابط بالفوتر ونافذة «تواصل معنا»، الأرقام تُضبط من صفحة إدارة النصوص |
| 7 | الخدمة المحددة بوقت تظهر بالبحث حتى لو غير متاحة، وليس الملغاة؛ العقار غير المتوفر لا يظهر | قواعد توفر موحّدة بالسيرفر (انظر البند 3) + حساب «متاح الآن» لحظياً حسب ساعات العمل بتوقيت فلسطين |
| 8 | الزائر بدون تسجيل يسمح له بمزايا محددة فقط | زر **«تصفح كزائر»** + حجب أرقام التواصل من السيرفر + نافذة «تتطلب تسجيل الدخول» للمزايا المقيّدة |
| 9 | وثيقة دليل التشغيل والاختبار | هذا الملف + سكربت اختبار آلي `tools/test-scenarios.mjs` + قاعدة اختبار محلية `database/local_test_seed.sql` |

## 2. التشغيل والإعداد

### 2.1 لا خطوات إلزامية على قاعدة البيانات
الجداول الجديدة تُنشأ تلقائياً عند تشغيل السيرفر (`CREATE TABLE IF NOT EXISTS`):

| الجدول (services_db) | الغرض |
|----------------------|-------|
| `provider_listings` | ربط المزود بعدة معالم (طبقة + رقم معلم). الربط القديم `users.service_layer/feature_id` يُرحَّل تلقائياً كـ «إعلان أساسي» |
| `listing_images` | صور الإعلانات (BYTEA). التخزين بقاعدة البيانات مقصود لأن النشر يستخدم `robocopy /MIR` الذي يحذف أي ملفات مرفوعة على القرص |
| `listing_ratings` | التقييمات المباشرة (تقييم واحد لكل مستخدم لكل إعلان، قابل للتعديل) |

> ملاحظة: إضافة خدمة جديدة تكتب في `service_all`، وإضافة عقار تكتب في جدول الطبقة (`ApartRent` / `ApartSale` / `LandSale`) بقاعدة `realestate`. السيرفر يكتشف الأعمدة الموجودة فعلاً بكل جدول ويكتب فيها فقط، ويُنشئ للأرض مضلعاً مربعاً حول النقطة المختارة مساحته = المساحة المدخلة.

### 2.2 متغيرات البيئة الجديدة (كلها اختيارية)

| المتغير | الافتراضي | الوصف |
|---------|-----------|-------|
| `PLATFORM_NAME` | `دليلك وين` | اسم المنصة إن لم يُضبط من لوحة الإدارة |
| `PLATFORM_WHATSAPP` | فارغ | رقم واتساب المنصة الافتراضي |
| `PLATFORM_PHONE` | فارغ | رقم هاتف المنصة الافتراضي |
| `MAX_IMAGES_PER_LISTING` | `8` | أقصى عدد صور لكل إعلان |
| `MAX_IMAGE_BYTES` | `2097152` (2MB) | أقصى حجم للصورة بعد الضغط |
| `MAX_LISTINGS_PER_PROVIDER` | `30` | أقصى عدد إعلانات للمزود (المشرف مستثنى) |
| `PLATFORM_TIMEZONE` | `Asia/Hebron` | المنطقة الزمنية لحساب «متاح الآن» حسب ساعات العمل |

### 2.3 ضبط اسم المنصة وأرقام التواصل
1. سجّل الدخول كمشرف ← افتح `/texts-admin.html`.
2. قسم **«اسم المنصة وأرقام التواصل»**: أدخل الاسم ورقم الواتساب ورقم الهاتف ← حفظ.
3. تظهر القيم خلال دقيقة بكل الصفحات. ترك الرقم فارغاً يُخفي زره.

> ⚠️ **مطلوب قبل الإطلاق:** أرقام واتساب وهاتف المنصة غير مضبوطة بعد (لا توجد أرقام حقيقية بالكود). بدونها لا يظهر زر التواصل العائم.

### 2.4 إخفاء/إظهار طبقة
- عدّل `globalExclusions` في `frontend-react/public/js/config.js` (ونسختيه بالجذر و`dist`).
- **السيرفر يلتقط التعديل تلقائياً خلال 5 ثوانٍ دون إعادة تشغيل**، ويطبّقه على كل المسارات.
- تقبل القائمة: اسم الخدمة (`electrician`)، المعرّف الداخلي (`rentLayer`)، اسم الجدول (`ApartRent`) أو الاسم العربي للعقارات.
- عند إخفاء تصنيف لا يستطيع المزود إضافة إعلانات جديدة له، وإعلاناته القديمة فيه تظهر بلوحته بشارة «التصنيف مخفي حالياً».
- للتأكد: `GET /api/layer-visibility` يرجع القائمة التي يطبّقها السيرفر فعلياً.

> حالياً كل طبقات الخدمات مخفية بـ `config.js` ما عدا (فلل أجار، فنادق) والعقارات الثلاثة، لذلك قائمة التصنيفات بصفحة «خدماتي» تعرض هذين فقط.

### 2.5 قواعد الحالة والظهور

| قيمة `status` | المعنى | الخدمة بالبحث | العقار بالبحث | على الخريطة |
|:---:|--------|:---:|:---:|:---:|
| `0` | متاح | ✅ «متاح الآن» (أو «مغلق حالياً» خارج ساعات العمل) | ✅ | ✅ |
| `1` | غير متاح (أوقفه المزود) | ✅ مع شارة «غير متاح حالياً» | ❌ | الخدمة ✅ / العقار ❌ |
| `2` | ملغي | ❌ | ❌ | ❌ |
| `end_date` منتهي | اشتراك منتهٍ = ملغي | ❌ | ❌ | ❌ |

- ترتيب نتائج الخدمات: المتاح الآن أولاً ثم الأعلى تقييماً.
- `auto_status` يُعاد حسابه لحظياً بكل استجابة (التريجر بقاعدة البيانات يحسبه فقط لحظة الكتابة، فكان يصبح قديماً مع مرور الساعات).
- المشرف يرى كل المعالم على الخريطة (حتى غير المتوفرة) ليتمكن من تحريرها.

## 4. دليل الاستخدام المختصر

### الزائر
1. من شاشة الترحيب اضغط **«تصفح كزائر بدون تسجيل»** (أو من نافذة الدخول).
2. يبقى وضع الزائر فعّالاً عند تحديث الصفحة خلال نفس الجلسة. فتح رابط موقع مشترك (`?x=&y=`) يدخل كزائر مباشرة.
3. للدخول لاحقاً: زر **«تسجيل الدخول / حساب جديد»** بشريط الهوية.

### المزود — إدارة الخدمات والعقارات
1. بعد الدخول يظهر بشريط الهوية زرّا **«خدماتي»** و**«عقاراتي»**.
2. **إضافة:** «إضافة خدمة/عقار» ← اختر التصنيف ← الاسم ورقم واتساب أو هاتف (أحدهما إلزامي) ← الحالة ← (للعقار: السعر والعملة والمساحة / للخدمة: ساعات العمل بصيغة `08:00-17:00` أو «متوفر 24 ساعة») ← حدد الموقع بالنقر على الخريطة أو «موقعي الحالي» ← حفظ.
3. بعد الحفظ تفتح نافذة الصور مباشرة: ارفع حتى 8 صور، والصورة الأولى هي الغلاف (يمكن تغييرها بـ «جعلها غلافاً»).
4. **تعديل:** زر «تعديل» على البطاقة (لا يمكن تغيير التصنيف بعد الإضافة).
5. **الحالة:** متاح / غير متاح / ملغي (انظر الجدول 2.5).
6. **حذف:** يحذف الإعلان وصوره نهائياً. الإعلان الأساسي المرتبط من الإدارة لا يُحذف (غيّر حالته إلى «ملغي»).
7. تبويبات الفلترة: الكل / متاح / غير متاح / ملغي. يظهر بكل بطاقة متوسط تقييمها.
8. طلبات الخدمة تصل للمزود على أي من خدماته (وليس فقط الخدمة الأساسية).

### المستخدم — التقييم
1. افتح أي خدمة أو عقار (بوب أب الخريطة أو بطاقة البحث بدون خريطة).
2. صندوق التقييم: المتوسط، عدد التقييمات، **تقييم الناشر** (متوسط كل إعلاناته وعددها)، وزر «التعليقات».
3. **«⭐ قيّم الآن»** ← اختر النجوم ← تعليق اختياري ← إرسال. يمكن تعديل التقييم لاحقاً. يصل للناشر إشعار بالتقييم.
4. التقييمات القادمة من طلب خدمة مكتمل تظهر بعلامة «✔ موثّق».

### المشرف
- ربط مزود بمعلم من «إدارة المستخدمين» كما كان؛ يتزامن تلقائياً مع جدول الإعلانات المتعددة.
- ضبط الاسم والأرقام من `/texts-admin.html`.
- إخفاء الطبقات من `config.js` (البند 2.4).

## 5. واجهات API الجديدة

| الطريقة والمسار | الصلاحية | الوصف |
|-----------------|----------|-------|
| `GET /api/my-listings/catalog` | مزود/مشرف | التصنيفات المتاحة للإضافة (بعد استبعاد المخفية) والحدود |
| `GET /api/my-listings?kind=service\|property` | مزود/مشرف | إعلاناتي مع الحالة وعدد الصور والغلاف |
| `GET /api/my-listings/:layer/:fid` | المالك/مشرف | تفاصيل إعلان + صوره |
| `POST /api/my-listings` | مزود/مشرف | إضافة إعلان (`layer`, `name`, `whatsapp`/`phone`, `x_coord`, `y_coord` بنظام EPSG:28191 …) |
| `PUT /api/my-listings/:layer/:fid` | المالك/مشرف | تعديل الحقول/الحالة/الموقع |
| `DELETE /api/my-listings/:layer/:fid` | المالك/مشرف | حذف (ليس للإعلان الأساسي) |
| `POST /api/my-listings/:layer/:fid/images` | المالك/مشرف | رفع صورة `{ image: "data:image/jpeg;base64,..." }` (JPG/PNG/WEBP، يُتحقق من بصمة الملف) |
| `DELETE /api/my-listings/images/:id` · `POST /api/my-listings/images/:id/cover` | المالك/مشرف | حذف صورة / تعيين غلاف |
| `GET /api/listing-images?layer&feature_id` · `GET /api/listing-images/:id` | عام | قائمة الصور / الصورة نفسها |
| `GET /api/listing-ratings?layer&feature_id` | عام (+ `my_rating` للمسجل) | التقييمات والمتوسط والتوزيع وتقييم الناشر |
| `POST /api/listing-ratings` · `DELETE /api/listing-ratings?layer&feature_id` | مسجّل | إضافة/تعديل تقييمي · حذفه |
| `POST /api/listing-ratings/summary` | عام | ملخص تقييمات عدة إعلانات دفعة واحدة |
| `GET /api/layer-visibility` | عام | الطبقات المخفية المطبّقة بالسيرفر |
| `GET /api/platform-contact` | عام | اسم المنصة ورقما الواتساب والهاتف |

تعديلات على مسارات قائمة: `search-features` و`search-features-batch` و`get-unique-values` (إخفاء الطبقات + قواعد التوفر + حجب التواصل للزائر)، `platform-stats` و`top-rated-providers` و`service-ratings` و`provider-linked-features` و`service-requests` و`log-contact-click` (إخفاء الطبقات + دعم المزود متعدد الإعلانات)، وبروكسي `/geoserver-proxy` (فلترة استجابات WFS GetFeature).

## 6. بيئة الاختبار المحلية

```bash
# 1) PostgreSQL 16 + PostGIS 3
createdb services_db && createdb realestate
psql -d services_db -f database/local_test_seed.sql
psql -d realestate  -f database/local_test_seed.sql

# 2) بديل GeoServer يقرأ من قاعدة الاختبار (اختياري، لاختبار الخريطة والبروكسي)
POSTGRES_USER=postgres POSTGRES_PASSWORD=*** node tools/mock-geoserver.mjs

# 3) السيرفر (.env): POSTGRES_* + JWT_SECRET + GEOSERVER_TARGET=http://127.0.0.1:3998/geoserver
npm start

# 4) الاختبار الآلي
BASE_URL=http://localhost:3000 node tools/test-scenarios.mjs
```

حسابات الاختبار (كلمة المرور `Test1234`): مشرف `0590000001`، مزود `0590000002`، مستخدم `0590000003`، مستخدم ثانٍ `0590000004`.
بيانات الاختبار تشمل: فيلا متاحة، فيلا غير متاحة (status=1)، فيلا خارج الدوام، فيلا ملغاة (status=2)، فيلا منتهية الاشتراك، خدمة من طبقة مخفية (كهربائي)، شقة متوفرة وشقة غير متوفرة.

> ⚠️ لا تشغّل `tools/test-scenarios.mjs` على قاعدة الإنتاج: ينشئ إعلانات وتقييمات وطلبات ويحذف بعضها.

### 7.3 ما لم يُختبر / ملاحظات
- **لم يُختبر على GeoServer الحقيقي ولا قاعدة الإنتاج** (الاختبار على بديل محلي ببنية مطابقة لما هو موثق). يُنصح بتجربة إضافة إعلان واحد على الإنتاج والتأكد من ظهوره على الخريطة (GeoServer يقرأ الجداول مباشرة، فلا يلزم نشر طبقات جديدة).
- إذا كانت جداول العقارات بالإنتاج تفتقد عموداً ما (مثل `currency` أو `whatsapp`)، يتجاهله السيرفر تلقائياً بدل الفشل.
- ملاحظة سابقة للتعديلات: سياسة CSP بـ helmet (`ENABLE_HELMET` غير `false`) تمنع السكربتات المضمّنة inline بالصفحات (مثل سكربت شاشة الترحيب). الملفات الجديدة كلها خارجية فلا تتأثر.
- خرائط الأساس الخارجية وخطوط Font Awesome لم تُحمَّل ببيئة الاختبار المعزولة (قيود شبكة)، وهذا لا يخص التعديلات.
