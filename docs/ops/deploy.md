# النشر والإعدادات

## كيف بيصير النشر

أي إضافة على فرع `main` بتشغّل `.github/workflows/deploy.yml` على سيرفر الويندوز (runner ذاتي):

1. **فحص قبل ما نلمس الإنتاج:** تثبيت مكتبات السيرفر والواجهة، فحص `server.js`، فحص الأنواع والكود، الاختبارات،
   وبناء الواجهة (`web/dist`). أي فشل هون = ما بينتشر شي.
2. **`tools/deploy-windows.ps1`:**
   - بيجهّز النسخة الجديدة بمجلد جانبي، وبياخذ نسخة احتياطية من الحالية.
   - بيوقف خدمة `mapsHusam`، بينسخ، وبيشغّلها.
   - بيفحص إنه الموقع رد على `http://127.0.0.1:3000/`.
   - **إذا ما رد، بيرجّع النسخة القديمة لحاله.**
3. ما بينسخ ولا بيحذف: `.env` و `.env.*` و `DB_Backups` و `GeoServerData`.
   أي ملف تاني بمجلد الموقع مش موجود بالمستودع **بينحذف** (`robocopy /MIR`).

السيرفر نفسه بيقدّم الواجهة من `web/dist`. الروابط القديمة (`/index.html`، `/admin-users.html`، `/dashboard.html`…)
بتتحوّل لحالها للصفحات الجديدة.

## الإعدادات (`.env`)

القائمة الكاملة مع الشرح بـ [`.env.example`](../../.env.example). المطلوب:
- `POSTGRES_HOST`، `POSTGRES_USER`، `POSTGRES_PASSWORD`.
- `JWT_SECRET`: نص عشوائي من 32 حرف أو أكثر. مع `NODE_ENV=production` السيرفر **ما بيقلع** بدونه.

القيم الحقيقية محفوظة برّا المستودع، بملف خاص عند صاحب المشروع.

## قاعدة البيانات

الجداول الجديدة بتنعمل لحالها لما السيرفر يقلع (`ensure…` بـ `server.js`). اللي لازم يدويًا مرة وحدة على قاعدة
جديدة بس: [`database/README.md`](../../database/README.md).

## GeoServer

لما ينضاف عمود لجدول طبقة، GeoServer ما بيشوفه لحتى يعيد قراءة الطبقة:
- **من الواجهة:** GeoServer ← Layers ← الطبقة ← Reload feature type.
- **أو:** Server Status ← Reset (بيمسح الذاكرة المؤقتة لكل الطبقات).

هالدمج بيبدّل الموقع كامل للنسخة الجديدة. بيحذف الصفحات القديمة، وبيغيّر طريقة النشر نفسها.

| # | شو | ليش |
|---|---|---|
| 1 | **`JWT_SECRET` موجود بإعدادات الإنتاج** (32+ حرف) | النسخة الجديدة بترفض تقلع بدونه بالإنتاج. النشر رح يرجع للقديم لحاله، بس الموقع ما بيتحدّث |
| 2 | **تعرف من وين الإنتاج بياخذ إعداداته** (`.env` بمجلد الموقع، أو متغيرات خدمة nssm) | النشر القديم على `main` كان بيمسح `.env` (ما كان مستثنى). الجديد بيستثنيه |
| 3 | الـ runner عليه Node 22، وصلاحية يوقف ويشغّل خدمة `mapsHusam` | النشر الجديد بيبني الواجهة على السيرفر وبيستخدم `Stop-Service` |

| 5 | ما في صور أو ملفات بالقاعدة بتأشّر على `/pic/…` أو ملفات قديمة بجذر الموقع | المجلدات القديمة (`pic/`، `js/`، `css/`…) رح تنحذف من السيرفر |
| 6 | حسام راجع وقرّر بنود [`docs/add-business.md`](../add-business.md) | ميزة جديدة بتفعّل حسابات وبتنشر نقاط |
| 7 | الإعدادات القديمة بتعدّت: المستودع **خاص**، وكلمات السر تغيّرت | تاريخ git العام فيه أسرار قديمة (بالملف الخاص) |
| 8 | تجربة كاملة على نسخة محلية فيها نسخة حديثة من قاعدة الإنتاج | الاختبارات التلقائية بتشتغل على قاعدة تجريبية صغيرة |

## بعد الدمج مباشرة

1. تابع تشغيلة النشر على GitHub (Actions) لحد ما تخلص بنجاح.
2. GeoServer ← Reload للطبقة `service_all` (عمود العملة الجديد `currency`).
3. افتح الموقع: الخريطة، البحث، دخول مدير، دخول مزوّد، وطلب خدمة كامل بين حسابين.
4. جرّب رابط قديم (مثلاً `/index.html`) لازم يحوّل للصفحة الجديدة.
5. على جوال حقيقي: الخريطة، «موقعي»، والإشعارات.

**إذا صار خلل بعد ما النشر نجح:** النسخة السابقة محفوظة جنب الموقع باسم `mapsHusam.__previous`. وقّف الخدمة،
انسخها مكان الموقع، وشغّل الخدمة.
**لا تعمل `git revert` للدمجة:** بيرجّع ملف النشر القديم، وهداك بيمسح `.env` من السيرفر.
