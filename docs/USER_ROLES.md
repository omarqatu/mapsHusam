# أدوار المستخدمين والأذونات (User Roles and Permissions)

## نظرة عامة

تطبق منصة خريطة خدمات فلسطين نظام التحكم في الوصول القائم على الأدوار (RBAC) لإدارة أذونات المستخدم والوصول إلى ميزات متنوعة. يحدد هذا المستند أدوار المستخدمين المختلفة، أذوناتهم، ومستويات الوصول.

## أدوار المستخدمين

### 1. المستخدم العادي (user)

**الوصف**: المستخدمون العاديون الذين يتصفحون المنصة، يبحثون عن الخدمات، ويطلبون الخدمات من مقدمي الخدمة.

**القدرات**:
- تصفح الخريطة التفاعلية
- البحث عن مقدمي الخدمات
- عرض معلومات المزود
- التواصل مع مقدمي الخدمات عبر الهاتف/واتساب
- تقديم طلبات الخدمة
- المحادثة مع مقدمي الخدمة (بعد قبول الطلب)
- تقييم ومراجعة مقدمي الخدمة
- عرض طلبات الخدمة الخاصة
- إدارة الملف الشخصي الخاص

**الأذونات**:
| الميزة | مستوى الوصول |
|---------|-------------|
| تصفح الخريطة | كامل |
| البحث عن الخدمات | كامل |
| التواصل مع المزود | كامل |
| طلبات الخدمة | إنشاء خاص |
| المحادثة | مع المزودين المقبولين |
| التقييمات | إنشاء لمقدمي الخدمة المستخدمين |
| إدارة الملف الشخصي | الملف الشخصي الخاص فقط |

**القيود**:
- لا يمكن الاستجابة لطلبات الخدمة
- لا يمكن إدارة حالة المزود
- لا يمكن الوصول إلى ميزات المسؤول
- لا يمكن عرض بيانات المستخدمين الآخرين
- لا يمكن تعديل بيانات طبقة الخدمة

### 2. مقدم الخدمة (provider)

**الوصف**: مقدمو الخدمات الذين يقدمون الخدمات من خلال المنصة. يمكنهم إدارة توفرهم، الاستجابة للطلبات، والتواصل مع المستخدمين.

**القدرات**:
- جميع قدرات المستخدم العادي
- ربط الملف الشخصي بميزات الخريطة
- إدارة حالة التوفر (متاح/مشغول)
- تحديث الموقع الجغرافي
- استلام طلبات الخدمة
- قبول/رفض طلبات الخدمة
- المحادثة مع المستخدمين الذين طلبوا الخدمات
- عرض الإحصائيات الخاصة
- عرض التقييمات والمراجعات
- إدارة بيانات طبقة الخدمة (الميزات المرتبطة)

**الأذونات**:
| الميزة | مستوى الوصول |
|---------|-------------|
| تصفح الخريطة | كامل |
| البحث عن الخدمات | كامل |
| التواصل مع المزود | كامل |
| طلبات الخدمة | استلام والاستجابة |
| المحادثة | مع المستخدمين الطالبين |
| التقييمات | عرض التقييمات الخاصة |
| إدارة الملف الشخصي | الملف الشخصي الخاص + الميزات المرتبطة |
| إدارة الحالة | التوفر الخاص |
| تحديثات الموقع | الميزات المرتبطة الخاصة |

**القيود**:
- لا يمكن الوصول إلى ميزات المسؤول
- لا يمكن عرض بيانات مقدمي الخدمة الآخرين
- لا يمكن تعديل ميزات مقدمي الخدمة الآخرين
- لا يمكن حذف حسابات المستخدمين
- لا يمكن تسجيل خروج المستخدمين بالقوة

### 3. المسؤول (admin)

**الوصف**: المسؤولون الذين لديهم وصول كامل للنظام لإدارة المستخدمين، مراقبة نشاط المنصة، والحفاظ على سلامة النظام.

**القدرات**:
- جميع قدرات المستخدم العادي
- جميع قدرات مقدم الخدمة
- إدارة جميع حسابات المستخدمين
- عرض وتعديل أدوار المستخدمين
- تسجيل خروج أي مستخدم بالقوة
- تعطيل/تمكين حسابات المستخدمين
- حذف حسابات المستخدمين
- عرض جميع طلبات الخدمة
- عرض إحصائيات المنصة
- إدارة إحصائيات نجاح المزود
- الوصول إلى لوحة تحكم المسؤول
- مراقبة سجلات النظام
- تكوين إعدادات النظام

**الأذونات**:
| الميزة | مستوى الوصول |
|---------|-------------|
| تصفح الخريطة | كامل |
| البحث عن الخدمات | كامل |
| التواصل مع المزود | كامل |
| طلبات الخدمة | عرض الكل |
| المحادثة | وصول كامل |
| التقييمات | عرض الكل |
| إدارة الملف الشخصي | جميع الملفات الشخصية |
| إدارة الحالة | جميع المستخدمين |
| تحديثات الموقع | جميع الميزات |
| إدارة المستخدمين | كامل |
| تكوين النظام | كامل |
| السجلات والمراقبة | كامل |

**لا قيود**:
- وصول كامل للنظام
- يمكن تعديل أي بيانات
- يمكن الوصول إلى أي ميزة
- يمكن تنفيذ أي إجراء إداري

## تعيين الدور

### تعيين الدور الافتراضي

- **التسجيلات الجديدة**: الدور الافتراضي هو `user`
- **ترقية المزود**: يجب على المسؤول ترقية يدوياً إلى `provider`
- **تعيين المسؤول**: يمكن للمسؤولين الحاليين فقط إنشاء مسؤولين جدد

### عملية تغيير الدور

#### المستخدم إلى المزود

1. يطلب المستخدم حالة المزود
2. يراجع المسؤول الطلب
3. يتحقق المسؤول من بيانات اعتماد المزود
4. يحدث المسؤول دور المستخدم إلى `provider`
5. يمكن للمستخدم الآن الوصول إلى ميزات المزود

#### المزود إلى المسؤول

1. يرشح المسؤول الحالي المزود
2. يراجع فريق المسؤول الترشيح
3. يوافق فريق المسؤول
4. يحدث المسؤول دور المستخدم إلى `admin`
5. يحصل المسؤول الجديد على وصول كامل للنظام

#### تخفيض الدور

1. يبدأ المسؤول تغيير الدور
2. يقدم المسؤول السبب
3. يحدث النظام دور المستخدم
4. يفقد المستخدم أذونات الدور السابق
5. يتم إخطار المستخدم بالتغيير

## تنفيذ التحكم في الوصول

### التفويض الخلفي

#### التحقق من رمز JWT

```javascript
function requireAuth(req, res, next) {
    const token = req.headers['authorization'];
    if (!token) {
        return res.status(401).json({ success: false, error: 'مطلوب المصادقة' });
    }
    
    try {
        const decoded = jwt.verify(token, process.env.JWT_SECRET);
        req.user = decoded;
        next();
    } catch (error) {
        return res.status(401).json({ success: false, error: 'رمز غير صالح' });
    }
}
```

#### برمجية وسيطة للتحقق من الدور

```javascript
function requireRole(role) {
    return (req, res, next) => {
        if (req.user.role !== role) {
            return res.status(403).json({ 
                success: false, 
                error: 'أذونات غير كافية' 
            });
        }
        next();
    };
}

function requireAdmin(req, res, next) {
    const adminUserId = req.headers['x-admin-user-id'];
    if (!adminUserId) {
        return res.status(403).json({ 
            success: false, 
            error: 'مطلوب وصول المسؤول' 
        });
    }
    
    // التحقق من دور المسؤول في قاعدة البيانات
    servicesPool.query(
        'SELECT role FROM users WHERE user_id = $1',
        [adminUserId],
        (err, result) => {
            if (err || result.rows[0]?.role !== 'admin') {
                return res.status(403).json({ 
                    success: false, 
                    error: 'غير مصرح به كمسؤول' 
                });
            }
            next();
        }
    );
}
```

### التفويض الأمامي

#### عرض واجهة المستخدم القائم على الدور

```javascript
function renderBasedOnRole(userRole) {
    if (userRole === 'admin') {
        renderAdminDashboard();
        renderUserManagement();
        renderSystemLogs();
    }
    
    if (userRole === 'provider' || userRole === 'admin') {
        renderProviderPanel();
        renderStatusToggle();
        renderLocationUpdate();
        renderIncomingRequests();
    }
    
    // جميع المستخدمين
    renderMap();
    renderSearch();
    renderServiceRequest();
}
```

#### فحص الوصول إلى الميزة

```javascript
function canAccessFeature(feature, userRole) {
    const permissions = {
        'user': ['map', 'search', 'contact', 'request', 'chat', 'rate'],
        'provider': ['map', 'search', 'contact', 'respond', 'chat', 'rate', 'status', 'location'],
        'admin': ['all']
    };
    
    if (userRole === 'admin') return true;
    return permissions[userRole]?.includes(feature) || false;
}
```

## اعتبارات الأمان

### الأمان القائم على الدور

1. **التحقق من جانب الخادم**: يجب إجراء جميع فحوصات الدور من جانب الخادم
2. **التحقق من الرمز**: يجب التحقق من رموز JWT على كل مسار محمي
3. **منع تصعيد الدور**: لا يمكن للمستخدمين ترقية دورهم الخاص
4. **مسؤولية المسؤول**: يجب تسجيل جميع إجراءات المسؤول
5. **إدارة الجلسة**: قدرة تسجيل الخروج بالقوة للحسابات المخترقة

### وراثة الإذن

- **المسؤول**: يرث جميع أذونات المزود والمستخدم
- **المزود**: يرث جميع أذونات المستخدم
- **المستخدم**: الأذونات الأساسية فقط

### تسجيل التدقيق

يجب تسجيل جميع تغييرات الدور وتعديلات الإذن:

```javascript
async function logRoleChange(adminId, targetUserId, oldRole, newRole, reason) {
    await servicesPool.query(
        `INSERT INTO role_change_log 
         (admin_id, target_user_id, old_role, new_role, reason, timestamp)
         VALUES ($1, $2, $3, $4, $5, NOW())`,
        [adminId, targetUserId, oldRole, newRole, reason]
    );
}
```

## أفضل الممارسات

### إدارة الدور

1. **مبدأ أقل الامتيازات**: يجب أن يكون لدى المستخدمين الأذونات الضرورية فقط
2. **مراجعة منتظمة**: مراجعة دور المستخدمين والأذونات بشكل دوري
3. **التوثيق**: توثيق تعيينات الدور والتغييرات
4. **عملية الموافقة**: تتطلب الموافقة لتغييرات الدور
5. **عملية الإلغاء**: عملية واضحة لإلغاء الوصول

### ممارسات الأمان

1. **مصادقة قوية**: المصادقة متعددة العوامل لحسابات المسؤول
2. **مهلة الجلسة**: تسجيل خروج تلقائي بعد عدم النشاط
3. **قيود IP**: تقييد وصول المسؤول إلى عناوين IP محددة (اختياري)
4. **سياسات كلمات المرور**: فرض متطلبات كلمة مرور قوية
5. **قفل الحساب**: قفل الحسابات بعد محاولات تسجيل الدخول الفاشلة

## التحسينات المستقبلية

### ميزات الدور المخطط لها

1. **أذونات دقيقة**: نظام إذن أكثر دقة
2. **أدوار مخصصة**: القدرة على إنشاء أدوار مخصصة
3. **مجموعات الإذن**: تجميع الأذونات لإدارة أسهل
4. **الوصول المؤقت**: تعيينات الدور محدودة بوقت
5. **التفويض**: السماح للمستخدمين بتفويض أذونات محددة

### الأمان المتقدم

1. **المصادقة متعددة العوامل**: لحسابات المسؤول
2. **المصادقة البيومترية**: لأمان محسّن
3. **الرموز المادية**: مفاتيح أمان مادية
4. **التحليل السلوكي**: كشف السلوك غير المعتاد
5. **المراقبة في الوقت الفعلي**: مراقبة حية لإجراءات المسؤول

## استكشاف الأخطاء وإصلاحها

### المشاكل الشائعة

#### المستخدم لا يمكنه الوصول إلى ميزة

1. تحقق من دور المستخدم في قاعدة البيانات
2. تحقق من أذونات الميزة للدور
3. تحقق من صحة رمز JWT
4. تحقق من تكوين البرمجيات الوسيطة
5. راجع وحدة تحكم المتصفح بحثاً عن أخطاء

#### تغيير الدور لا يسري

1. امسح ذاكرة التخزين المؤقت للمتصفح
2. تحقق من تحديث قاعدة البيانات
3. تحقق من انتهاء صلاحية رمز JWT
4. أجبر المستخدم على إعادة تسجيل الدخول
5. راجع سجلات الخادم

#### رفض وصول المسؤول

1. تحقق من دور المسؤول في قاعدة البيانات
2. تحقق من رأس معرف مستخدم المسؤول
3. تحقق من رمز JWT
4. تحقق من تكوين البرمجيات الوسيطة
5. راجع سجلات الخادم
