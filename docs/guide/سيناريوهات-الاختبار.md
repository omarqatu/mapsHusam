# سيناريوهات الاختبار — خريطة الخدمات الفلسطينية

لكل سيناريو رقم (ح-01 …)، خطوات، ونتيجة متوقعة. إذا اختلفت النتيجة، سجّل: رقم السيناريو، الحساب، الجهاز والمتصفح،
عرض الشاشة، ولقطة شاشة.

## تجهيز بيئة الاختبار

### الحسابات

على نسخة التطوير (`dev/dev.sh seed`) توجد هذه الحسابات:

| الدور | رقم الجوال | كلمة المرور |
|-------|-----------|-----------|
| مشرف | 0590000001 | Admin#12345 |
| مزوّد (مربوط بخدمة سباك) | 0590000002 | Provider#12345 |
| مستخدم | 0590000003 | User#12345 |

على نسخة الإنتاج لا تُستخدم هذه الحسابات؛ أنشئ حسابات تجربة وامسحها أو عطّلها بعد الانتهاء.

### التشغيل المحلي

```bash
dev/dev.sh db-up && dev/dev.sh seed    # قاعدة البيانات + الحسابات
dev/dev.sh server                      # الخادم على :3000
cd web && npm install && npm run dev   # الواجهة على :5173 (أو أول منفذ متاح)
```

### حسابان في نفس الوقت

السيناريوهات التي فيها طرفان (طلب ← قبول) تحتاج متصفحين، أو نافذة عادية ونافذة خاصة، كل واحدة بحساب.

## السيناريوهات

### ح-01 | التسجيل

| الخطوات | النتيجة المتوقعة |
|--------|-----------------|
| من صفحة الدخول اضغط «إنشاء حساب جديد» | تظهر الشروط مع مربعين للموافقة؛ زر المتابعة معطّل حتى يُعلَّم المربعان |
| علّم المربعين → تابع | يظهر نموذج التسجيل: الاسم، المقدمة (+970/+972)، رقم الجوال، كلمة المرور |
| أدخل رقماً لا يبدأ بـ 05 أو ليس 10 أرقام | رسالة خطأ تحت حقل الجوال، ولا يُرسل شيء |
| كلمة مرور أقل من 6 أحرف | رسالة خطأ تحت كلمة المرور |
| بيانات صحيحة → «إتمام التسجيل» | الحساب يُنشأ **مفعّلاً**، والمستخدم يدخل تلقائياً بدون صفحة دخول |
| كرر بنفس الرقم | رسالة أن الرقم مسجّل مسبقاً |
| علّم «عندي نشاط تجاري وأريد إضافته على الخريطة» أثناء التسجيل وعبّئ بياناته | بعد التسجيل ينتقل لصفحة «أضف نشاطك»، والطلب ينتظر موافقة المشرف |
| سجّل أكثر من 5 حسابات من نفس الجهاز خلال ساعة | السادس يُرفض برسالة، ويعود يقبل بعد ساعة |

**الاختبار الآلي:** `auth.live.test.ts`, `RegisterPage.test.tsx`

### ح-05 | إضافة خدمة (3 خطوات)

| الخطوات | النتيجة المتوقعة |
|--------|-----------------|

| ارفض إذن الموقع | الخريطة تفتح على المنطقة العامة، وتقدر تختار يدوياً |

### ح-10 | طلب معاينة عقار والموعد

قبل البدء: اربط عقاراً بحساب المزوّد (المشرف ← تعديل المستخدم ← الربط)، أو استخدم شقة أُضيفت في ح-06.

| الخطوات | النتيجة المتوقعة |
|--------|-----------------|
| المستخدم يفتح العقار | زر «اطلب معاينة» بدل الاتصال المباشر |
| يرسل الطلب ويقبله المالك | في أعلى الدردشة شريط «موعد المعاينة» مكتوب فيه «لسا ما تحدد موعد» |
| المستخدم يضغط «حدّد موعد» ← «بكرا ١٠ الصبح» | الموعد يظهر للطرفين، والمالك يصله إشعار |
| المالك يضغط «غيّر» ويختار يوماً وساعة | الموعد يتغيّر، والمستخدم يصله إشعار |
| اختر وقتاً في الماضي | «اختر وقتاً قادماً، مش بالماضي.» |
| اختر موعداً بعد أكثر من 90 يوماً | «الموعد لازم يكون خلال ٩٠ يوماً.» |
| «ألغِ الموعد» | يرجع «لسا ما تحدد موعد» |
| المالك قبل القبول | لا يقدر يحدد موعداً قبل ما يقبل الطلب |
| الطرفان «تم الاتفاق» | الأرقام تظهر، والمستخدم يقيّم العقار |

**الاختبار الآلي:** `viewing.live.test.ts`, `appointment.test.ts`

## للمطورين

```bash
cd web && npm run typecheck && npm run lint && npm test            # فحوصات الواجهة
cd web && VITE_LIVE_API=http://localhost:3000 npm test             # + اختبارات على الخادم الحقيقي
cd web && npm run e2e                                              # Playwright: عرض 1440 و390
npm test                                                           # اختبارات الخادم (lib/*.test.js)
```

**ملاحظة:** اختبارات البحث والعدادات الحية (`search.live.test.ts`) تفشل إذا كان إعداد «إظهار وإخفاء» في
قاعدة التطوير يخفي طبقات الخدمات. أظهر كل الطبقات قبل تشغيلها، أو رجّع الإعداد بعدها كما كان.
